# 통합 문서관리 1차 퍼블리싱

- 작성일: 2026-11-12 (한국시간, Asia/Seoul)
- 상태: 1차 퍼블리싱 구현 및 검증 완료
- 기준: [AI Agent 아키텍처 및 통합 문서관리 퍼블리싱 설계](../../history/2026-11-12/AI-Agent-아키텍처-및-통합문서관리-퍼블리싱-설계.md)의 최신 내용을 다시 읽고 적용
- 구현 범위: 공통 셸·대시보드·팀공유·개인/프로젝트/관리자 설정·프로젝트 작업 탭·샘플 상호작용
- DB 변경: **없음**. DB 연결, DDL/DML, 마이그레이션 및 실데이터 변경을 수행하지 않음.

## 1. 주요 변경사항

### 공통 레이아웃과 테마

- 240px 좌측 패널과 우측 헤더·본문·푸터를 구성했다. 로고와 헤더는 같은 CSS 변수로 높이 64px를 공유한다.
- 사이드바에 대시보드, 팀공유, 개인설정, 프로젝트설정, 관리자설정과 하단 로그아웃 버튼을 제공한다.
- 현재 화면·프로젝트·탭에 맞는 breadcrumb와 메뉴 활성 상태를 표시한다.
- 1024px 미만에서는 모바일 메뉴 드로어로 전환한다. 네이티브 dialog의 Escape 닫기와 포커스 복원을 적용했다.
- 라이트·다크 토큰, 마젠타 포인트와 시스템 한글 폰트를 적용했다. 초기 테마를 첫 페인트 전에 적용한다.
- 테마만 브라우저 저장소에 보관한다. 저장소 접근이 차단되어도 라이트 초기화와 테마 전환이 동작한다.
- 빈 데이터·검색 결과 없음·로딩·오류·권한 없음과 찾을 수 없음 화면을 제공한다.

### 업무 화면과 샘플 관계

- 프로젝트 3개, 문서 18개, 요구사항 18개, 변경 사례 3개를 서로 연결한 fixture를 구성했다.
- 대시보드 요약은 동일 fixture에서 계산한다. 프로젝트를 선택하면 카드·목록·변경 영향이 같은 범위로 바뀐다.
- RFP 분석 → 요구사항 구조화 → 설계서 초안 → 변경 영향·버전 → 산출물 흐름을 탐색할 수 있다.
- 프로젝트 안에서 개요, RFP, 요구사항, 문서 생성, 변경 영향, 산출물 여섯 탭을 제공한다.
- 요구사항 상세에 ID, 내용, 원문 버전·페이지/절, 관련 기능, 연결 산출물을 표시한다.
- 기능·화면·WBS·아키텍처·DB 명세와 RFP의 읽기 전용 미리보기를 제공한다.
- 문서·요구사항 상세와 탭·검색·필터는 URL로 열고 복원한다. 잘못된 탭은 개요로 정규화하고, 다른 프로젝트의 상세 항목은 표시하지 않는다.
- 팀공유에서 프로젝트·상태·검색 조건으로 문서를 찾고 필터를 초기화할 수 있다.
- 개인·프로젝트 설정은 임시 입력·초기화를 제공한다. 프로젝트설정은 사용자가 편집 대상을 직접 선택한다.
- 내부 링크 및 프로젝트 선택으로 이동할 때 미저장 입력의 폐기를 확인하고, 새로고침·창 닫기에는 브라우저 기본 경고를 등록한다.
- 관리자 화면에는 일곱 Agent 구성요소 상세, 정책, 실행·감사 로그, 사용자·역할 시안을 제공한다.
- 실제 업로드·다운로드·AI 실행·영구 저장·공유·로그아웃에는 준비 중 또는 데모 안내를 표시한다. 실제 처리 성공으로 오인할 메시지를 사용하지 않는다.

### 구조와 문서

- 대시보드를 `app/(workspace)/page.tsx`로 이동하여 모든 업무 화면이 하나의 셸을 공유하게 했다. 루트에 같은 `/` 라우트를 중복 생성하지 않았다.
- 루트 레이아웃은 Server Component로 유지하고, Provider 단위 Zustand Store로 UI 상태와 프로젝트 문맥을 분리했다.
- 기본 Next.js 안내·메타데이터·영문 언어 설정을 서비스 화면과 한국어 메타데이터로 교체했다.
- 외부 폰트 다운로드 의존성을 제거하고 기존 패키지와 Next 설정은 유지했다.
- `README.md`, `AGENTS.md`, `CLAUDE.md`에 실제 구조·제약·실행·검증 방법과 작업 기록을 반영했다.
- Next.js가 개발 서버 실행 시 생성한 AGENTS 자동 관리 블록은 보존하고 프로젝트 지침을 추가했다.

## 3. DB 및 외부 연동

이번 단계에는 DB 변경이 필요하지 않다. 설계 문서가 1차에서 제외한 인증·Turso CRUD·파일 저장소·실제 Agent 실행을 임의로 구현하지 않았다.

`@libsql/client` 등 기존 의존성은 그대로 보존했다. 환경 변수나 비밀번호·API 키·토큰을 추가·조회·기록하지 않았다. 화면에 표시된 이름·이메일·권한·로그는 샘플이다.

브라우저 검증 그룹:

1. 대시보드 집계, 지정 메뉴, 로고·헤더 동일 높이.
2. 네 가지 뷰포트에서 반응형 배치와 푸터.
3. 테마 전환·재접속 유지 및 라이트·다크 주요 텍스트 대비.
4. 모바일 메뉴의 Escape 닫기와 버튼 포커스 복원.
5. 요구사항 근거 상세·모달·탭 이동 후 브라우저 뒤로가기.
6. 문서 미리보기, 잘못된 탭 정규화, 타 프로젝트 상세 차단.
7. 프로젝트 편집 대상 선택, 미저장 이동 취소/허용, 이동 후 임시 입력 초기화.
8. 팀공유 검색·필터 초기화와 일곱 Agent 구성요소 상세.
9. 문서 생성 샘플, 존재하지 않는 프로젝트, 개발용 로딩·빈 데이터·오류·권한 없음 상태.
10. localStorage 접근이 차단된 상황의 테마 초기화·전환.
11. 브라우저 예외 및 console error 없음.

원시 결과는 [검증결과 JSON](검증결과.json)에 보관했다. 브라우저 검증은 데스크톱 Chrome의 뷰포트 기반 검증이며, 실물 모바일 기기·Safari·Firefox 및 실제 화면낭독기 검증은 수행하지 않았다. 대비 수치는 검사한 토큰 조합의 결과이며 전체 접근성 인증을 의미하지 않는다.

### 검증 중 수정한 사항

- 미사용 import 4건을 제거하여 린트 경고를 해소했다.
- CSS 우선순위로 데스크톱에 보이던 모바일 메뉴 버튼에 명시적 반응형 표시 규칙을 적용했다.
- 390px에서 표의 화면낭독기용 absolute 요소가 스크롤 컨테이너 밖으로 넘치는 문제를 확인하고 `.table-wrap`에 위치 기준을 설정했다.
- 개발용 상태 미리보기에서도 페이지 자식 트리를 유지하도록 보완하여 Next.js instant-navigation의 dropped-segment 진단을 해소했다.
- 검증용 브라우저가 생성한 파일을 `.local/`에 격리하고 린트 대상에서 제외했다.
- 브라우저 자동화의 고정 포트 충돌·시작 지연을 피하도록 브라우저가 할당한 DevTools 포트를 사용했다. Escape 입력과 포커스도 실제 키 동작에 맞게 검증했다.
- 최초 샌드박스 검증은 기존 pnpm 의존성 읽기 EPERM으로 실행되지 않았다. 허용된 확장 실행으로 재검증했고 최종 린트·타입·빌드가 통과했다.

## 6. 미완료 사항과 후속 범위

1차 퍼블리싱 범위의 미완료 구현은 없다. 아래는 설계에서 분리한 후속 범위다.

- 인증·조직·프로젝트·문서별 실제 권한, 로그인·로그아웃 및 초대·공유.
- 실제 Turso 엔진·SDK 확정, Repository·스키마·마이그레이션·버전·관계 저장.
- PDF/DOCX 업로드·파싱·OCR, 객체 저장소, 편집기, Excel/Word 등 내보내기.
- LLM 공급자·모델, Knowledge 검색, 실행 가능한 Prompt/Skill/Tool/Memory/Workflow/Guardrail과 Worker.
- Agent 실행 한도·품질 평가, 장기 선호 동기화·보존·삭제 정책.
- 정식 로고·최종 브랜드 및 실기기·다른 브라우저 검증.

다음 구현 요청에서는 사용자에 의해 수정되었을 수 있는 기준 설계와 본 기록을 다시 읽고 대상 단계를 확정한다. 현재 프리뷰는 `pnpm dev`로 재개할 수 있으며, DB나 외부 서비스 키는 필요하지 않다.
